# Reproducibility notes

## Release scope

Version `v1.3.0` reproduces the figures, source-data relationships, corpus totals, review-burden calculations, and readiness-anchor summaries used in the revised manuscript.

The release separates three kinds of material:

1. locked record-level decisions in `data/`;
2. derived plotting and summary inputs in `source_data/`;
3. deterministic validation and figure code in `scripts/`.

## Exact correspondence with the journal submission

The eleven supplementary-data CSVs and five source-data CSVs are present byte for byte in this repository under concise public filenames. `SUBMISSION_FILE_MAP.csv` records, for each journal-submission filename, the corresponding repository path, byte size, and SHA-256 checksum.

The public archive deliberately excludes the manuscript and reporting documents, rendered figure copies supplied separately to the journal, upload-wrapper ZIP files, author-review working sheets, and internal quality-control artifacts. Those files are not required to reproduce the released analyses. The five figures are regenerated from the public scripts and locked source data.

## Deterministic outputs

Running:

```bash
python3 scripts/rebuild_all.py
```

performs the following sequence:

1. validates all locked tables, cross-table relationships, and the author-maintained 16-file submission/repository checksum contract;
2. generates Figures 1–3 and Supplementary Figures S1–S2 in `figures/`;
3. reruns the release validator with exact PNG integrity, dimension, and checksum checks.

`SUBMISSION_FILE_MAP.csv` is updated only as an explicit release-authoring action and is not regenerated by `rebuild_all.py`.

After a successful strict rebuild, the deterministic public payload can be
recreated with:

```bash
python3 scripts/build_release_archive.py --output ../AI_urology_andrology-v1.3.0.zip
```

The builder packages an explicit file contract with fixed path order,
permissions, timestamp and compression settings, verifies source/archive byte
identity, and writes a manifest and SHA-256 sidecar next to the ZIP. It does
not invoke a network operation. The `.zip` and both sidecars must resolve
outside the repository root, preventing an output collision from modifying a
release source. Git/Zenodo publication remains a separate author-controlled
action.

The default command is the strict reference-environment check and therefore
requires the five PNG files to match the release checksums byte for byte. On a
different operating system or font-rendering stack, run:

```bash
python3 scripts/rebuild_all.py --portable
```

Portable mode still validates every locked data relationship and scientific
invariant, then requires all five outputs to be structurally valid PNGs with
the declared dimensions. It deliberately does not treat host-specific PNG byte
differences as scientific failures.

The intended PNG dimensions are:

- Figure 1: 4,200 × 5,400 pixels;
- Figure 2: 4,200 × 4,800 pixels;
- Figure 3: 4,200 × 4,680 pixels;
- Supplementary Figure S1: 4,200 × 2,880 pixels;
- Supplementary Figure S2: 4,200 × 3,060 pixels.

The byte-exact reference render was produced with Python 3.12.0 on macOS 26.5.2 (arm64), Matplotlib 3.10.8 using the `macosx` backend, and FreeType 2.6.1. Matplotlib resolved the regular and bold sans-serif faces to DejaVu Sans with these SHA-256 checksums:

- `DejaVuSans.ttf`: `3fdf69cabf06049ea70a00b5919340e2ce1e6d02b0cc3c4b44fb6801bd1e0d22`
- `DejaVuSans-Bold.ttf`: `b184b89e3c1075f22f6b71575b6fc20d4972b3cfd3b23322ca6fd596dcaef167`

`requirements.lock.txt` records the complete pinned Python dependency closure for that tested environment. It is a reference environment snapshot, not a cross-platform wheel-hash lock or container image; other platforms may reproduce the data and layout while producing different PNG bytes.

## Independently derivable checks

`scripts/validate_release.py` independently checks that:

- the 2,892 Data 4 PMIDs equal the Data 2 analytic-include set and retain the same operational analysis group;
- the 1,270 Data 11 outcomes are 797 Include, 13 Operational-analysis-group correction, 106 Context only, and 354 Exclude;
- the exact 13 original-to-final operational-analysis-group corrections match the frozen author-approved mapping;
- the exact 40 PubMed-metadata-confirmed non-English PMIDs are excluded under E09 in Data 2 and Data 11 and absent from Data 4;
- the two case-report-labelled boundary records are represented in Data 11 and remain included with PubMed-abstract or PMC-full-text validation evidence;
- `data/boundary_evidence.csv` contains exactly those 40 language-boundary records, the two case-report exceptions, and three full-text scope confirmations with primary locators and frozen snapshot hashes;
- every Data 11 row records the triggering rule identifier(s), evidence level, and a non-empty record-specific rationale;
- operational-analysis-group totals, publication trends, review burden, and PRISMA arithmetic reconcile;
- Figure 2 bubble counts derive from prospective or external/multicentre validation fields in the 38-anchor matrix;
- Data 5 equals the Supplementary Figure S2 source data and Data 8 equals the Figure 2 source data;
- all 16 submission CSV mappings retain their declared byte size and SHA-256 checksum;
- Figure 3 keeps contextual exemplars separate from the four corpus-supported readiness tiers.

## Outputs requiring external access

The PubMed harvester can rerun the search strategy, but PubMed records and indexing can change. A live rerun therefore creates a new search snapshot rather than the locked 4 April 2026 corpus.

The historical 7,264-record union-level table and 1,341 record-level prescreen dispositions were not retained. Their upstream counts are documented arithmetically but cannot be reconstructed at row level; all 5,923 formal screening decisions onward are included.

The ten mutually exclusive `Operational_Analysis_Group` values are descriptive operational groups, not query-route shares, a clinical-content prevalence estimate, or a formal taxonomy. The field was initialized from the recorded primary search-stream assignment and corrected for 13 author-verified content mismatches. `Search_Query_Tags` retains the recorded query-level tags and is the authoritative retrieval-provenance field. The historical rule used to choose one primary group for records retrieved by multiple queries was not retained and is not deterministically reconstructible; the release therefore does not claim that a fresh run would recreate that historical primary-group assignment.

The searches did not apply a publication-language filter; English-language eligibility was applied during screening. Immediately before freezing, a complete title-pattern language-boundary scan of the 2,932-record provisional set identified 44 bracket-initial titles. Four used radionuclide notation and remained eligible. Official PubMed XML confirmed that the remaining 40 publications lacked an English (`eng`) code, and all 40 were excluded under E09. Two case-report-labelled records were explicitly verified and retained because substantive AI validation was documented.

The four raw XML capture files identified by the hashes in `data/boundary_evidence.csv` are author-held quality-control artifacts and are not part of the public archive. They comprise one PubMed XML metadata capture and three PMC full-text XML capture files. The released CSV freezes the decisive extracted fields, official locators, access time, and capture-file hashes. Live PubMed records can change, and the three PMC full-text capture files are excluded pending article-specific redistribution-rights review.

The seed and exact command used for the historical random AI-exclusion audit sample were not retained. The released data preserve sample membership and decisions, but they cannot reproduce the original random draw exactly.

The AI-assisted screening-support script additionally requires abstracts, API access to the selected language-model backend, and the prompt/schema reported in the Supplementary Information. Abstracts are intentionally absent from the public screening database.

Because PubMed metadata and model reasoning are untrusted text inputs, the
live utilities write two coordinated views: canonical unmodified JSON Lines
(`*.raw.jsonl`) and a spreadsheet-facing CSV in which any text whose first
non-whitespace character is `=`, `+`, `-` or `@` is prefixed with an
apostrophe. CSV quoting alone does not neutralize spreadsheet formulae. Each
run manifest records the safety strategy and number of transformed cells.
The screening utility verifies and reads the raw companion by default; a
CSV-only legacy input requires the explicit `--allow-csv-only-input` override.

Publication-gate licence profiles bind every approved licence file by relative
path, SPDX identifier, and SHA-256 checksum, in addition to requiring matching
README, CFF, and Zenodo declarations. No profile is inferred by the code.
Licence files must be regular non-symlink files within the repository and carry
exactly one matching SPDX marker.

The production run used model identifier `claude-sonnet-4-20250514`, batches of 15 records, and `max_tokens=4096`; temperature was not explicitly set. The public support script requires an explicit output location and records run metadata, but it does not recreate historical human decisions.

## Human decisions

Human screening, adjudication, full-text resolution, final eligibility verification, and consensus-based readiness staging are represented in the released tables and are not regenerated by code. The repository supports auditability of the recorded decisions and reproducibility of their downstream calculations; it does not claim to reproduce the human judgments themselves.

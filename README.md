# AI in Urology and Andrology Reproducibility Repository

This repository contains the public data and code required to reproduce the review workflow outputs for:

> Clinical readiness of artificial intelligence in urology and andrology: a PubMed-indexed scoping review and evidence map

## Layout

- `data/`: core input tables and minimal workflow metadata
- `source_data/`: source-data tables corresponding to generated figures
- `assets/`: image panels required for the translation/collaboration figure
- `scripts/`: retrieval, screening, and figure/table generation scripts

Generated figure files are not stored in the repository. They are created in `figures/` when the scripts are run.

## Core data

- `screening_database.csv`: screened PubMed-indexed record set without abstract text
- `included_records.csv`: final included record set
- `screening_counts.json`: counts required to rebuild the screening flow diagram
- `pubmed_search_strings.csv`: PubMed search strings
- `top_journals.csv`: journal count table
- `readiness_matrix.csv`: readiness assignments by clinical task
- `reporting_frameworks.csv`: reporting and governance framework table
- `readiness_anchor_sources.csv`: anchor evidence source table
- `anchor_evidence_matrix.csv`: priority translational evidence matrix
- `readiness_anchor_summary_by_use_case.csv`: summary of anchor evidence by use case
- `review_paradox_by_domain.csv`: review and non-original publication burden by domain
- `ai_only_include_audit.csv`: human audit table for AI-only included records
- `tiered_readiness_summary.csv`: tiered readiness summary table

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

For an exact local environment snapshot, use `requirements.lock.txt`.

## Rebuild outputs

```bash
python3 scripts/rebuild_all.py
```

The individual rebuild scripts remain available in `scripts/` if a single figure or table needs to be regenerated.

## Retrieval and screening

```bash
python3 scripts/pubmed_harvest.py --email your_email@example.com
python3 scripts/ai_screening.py --input ../data/screening_master.csv --output ../data/screening_master_screened.csv
```

The harvester writes `data/screening_master.csv`; that live-retrieval file is not included in the locked public release because it contains abstracts.

## Notes

- The public screening table does not include abstracts.
- Human screening, adjudication, and audit decisions are represented in the released decision tables and are not regenerated by code.
- Rerunning PubMed retrieval creates a new live search snapshot, not the locked review corpus.
- The translation/collaboration figure depends on the two panel images in `assets/`.

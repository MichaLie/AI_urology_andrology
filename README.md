# AI in urology and andrology clinical-readiness evidence map

This repository contains the locked data tables, source data, and Python scripts accompanying the manuscript:

> Clinical readiness of artificial intelligence in urology and andrology: a PubMed-indexed scoping review and evidence map

Release `v1.3.0` is a static research-data and code release, not a live updating database.

## Dataset summary

- Search source: PubMed/MEDLINE
- Search date: 4 April 2026
- Search period: 1 January 2020 to 4 April 2026
- Records entering title and abstract screening: 5,923
- Final analytic corpus: 2,892 published journal records
- Final eligibility-verification table: 1,270 records
- Verification outcomes: 797 included, 13 operational-analysis-group corrections, 106 context only, and 354 excluded
- Readiness evidence: 38 in-corpus anchors and 8 separately labelled extracorpus contextual exemplars
- Scope: urology, andrology, and adjacent male sexual and reproductive health AI literature
- Excluded by design: urolithiasis

## Repository contents

- `data/`: locked screening, eligibility-verification, review-burden, and readiness tables
- `source_data/`: source data for Figures 1–2 and Supplementary Figures S1–S2
- `scripts/`: retrieval and screening-support utilities, figure builders, and release validation
- `SUBMISSION_FILE_MAP.csv`: byte sizes and SHA-256 checksums linking the 16 journal CSVs to their repository copies
- `REPRODUCIBILITY.md`: detailed provenance, validation rules, platform notes, and scope limitations

Figures are generated from the locked tables and are not stored in the repository.

## Reproduce the outputs

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python3 scripts/rebuild_all.py
```

Use `requirements.lock.txt` for the tested dependency snapshot. On another operating system or rendering stack, run `python3 scripts/rebuild_all.py --portable` to retain all data and scientific checks without requiring byte-identical PNG files.

## Scope and provenance

The public screening database does not contain abstracts. Human screening, adjudication, eligibility verification, and readiness staging are represented in the released tables but are not regenerated by code. Rerunning PubMed retrieval creates a new search snapshot rather than the locked review corpus.

`Operational_Analysis_Group` is a descriptive grouping used for corpus summaries; `Search_Query_Tags` is the authoritative retrieval-provenance field. The eight contextual exemplars are excluded from corpus totals and Figure 2 bubble counts. Full provenance and limitations are documented in `REPRODUCIBILITY.md`.

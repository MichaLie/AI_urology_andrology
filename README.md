# AI in urology and andrology clinical-readiness evidence map

This repository contains the versioned data tables, source-data files, and scripts accompanying the manuscript:

> Clinical readiness of artificial intelligence in urology and andrology: a PubMed-indexed scoping review and evidence map

The release provides a locked PubMed-indexed evidence-map corpus and reproducibility materials for the manuscript figures, tables, and supplementary data. It is a static research-data release rather than a live updating database.

## Dataset summary

- Search source: PubMed/MEDLINE
- Search date: 4 April 2026
- Search period: 1 January 2020 to 4 April 2026
- Screened records: 5,923
- Final analytic set: 3,352 published journal records
- Scope: urology, andrology, and adjacent male sexual and reproductive health artificial-intelligence literature
- Excluded by design: urolithiasis

## Layout

- `data/`: locked data tables and workflow metadata
- `source_data/`: source-data tables corresponding to manuscript figures
- `scripts/`: PubMed retrieval, screening-support, and figure/table generation scripts

Generated figure files are not stored in the repository. They are created in `figures/` when the scripts are run.

## Core data

- `screening_database.csv`: screened PubMed-indexed record set without abstract text
- `included_records.csv`: final included record set
- `screening_counts.json`: counts required to rebuild the screening flow diagram
- `pubmed_search_strings.csv`: PubMed search strings
- `top_journals.csv`: journal count table
- `readiness_matrix.csv`: readiness assignments by clinical task, including workflow-value criteria/rationale and corpus-status fields used for Figure 2 interpretation
- `reporting_frameworks.csv`: reporting and governance framework table
- `readiness_anchor_sources.csv`: anchor evidence source table
- `anchor_evidence_matrix.csv`: priority translational evidence matrix
- `readiness_anchor_summary_by_use_case.csv`: summary of anchor evidence by use case
- `review_paradox_by_domain.csv`: review and non-original publication burden by domain
- `ai_only_include_audit.csv`: human verification table for AI-only included records
- `tiered_readiness_summary.csv`: tiered readiness summary table

## Reproduce outputs

Install dependencies:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

For an exact local environment snapshot, use `requirements.lock.txt`.

Rebuild the figures and derived source-data outputs:

```bash
python3 scripts/rebuild_all.py
```

The individual rebuild scripts remain available in `scripts/` if a single figure or table needs to be regenerated.

## Search rerun and screening support

```bash
python3 scripts/pubmed_harvest.py --email your_email@example.com
python3 scripts/ai_screening.py --input ../data/screening_master.csv --output ../data/screening_master_screened.csv
```

The harvester writes `data/screening_master.csv`; that live-retrieval file is not included in the locked public release because it contains abstracts.

## Important notes

- The public screening table does not include abstracts.
- Human screening, adjudication, and verification decisions are represented in the released decision tables and are not regenerated by code.
- Rerunning PubMed retrieval creates a new live search snapshot, not the locked review corpus.
- The translation/collaboration figure is generated directly by script in the locked release.
